方法 · 规范

一篇论文怎么变成
一份能跑的档案

这一页写两件事：复现一篇论文时按什么顺序做，以及往这个站点加一篇新复现时要遵守什么格式。 前者是为了让结果可信，后者是为了让读者换一篇论文时不用重新适应。

01Flow

六步流程

顺序不能颠倒。第 2 步错了，后面每一步的指标都会失去意义——这是复现里最贵的一类错误。

01

先定「复现到哪一层」

论文通常有三层：装置与物理链路、网络结构、训练配方。三层都想复现，往往一层都做不实。 先明确这一篇只做哪一层，并把不做的那几层写成清单——它会直接变成最后那张差异表。

02

把正演写成可微的，并对齐口径

把论文的求解器换成可微等价物（BPM、角谱、分片传播）。关键是口径一致：采样间距、归一化、孔径定义， 训练和验证必须用同一套。口径错了不会报错，只会让损失停在某个值不动。

03

用同一套物理标数据

训练集、验证集、最终验收，全部走第 2 步那条链路。不要在验证时换成更精确的求解器—— 那样得到的是「训练目标与评估目标不一致」的假指标。要评估精度损失，就单独做一次对照实验并写进差异表。

04

训练，并且看分布不看单点

代理模型的误差要在误差分布上看：中位数、90 分位、最差样本。平均值漂亮但长尾很糟的模型， 到了逆向设计阶段会稳定地毁掉某一类结构。同时留一个基线（随机、均值、或原文数字）做参照。

05

设计，再用高分辨率前向复核

逆向设计出来的结构，必须放回物理里重新算一遍。代理模型说「相位误差 0.02 rad」但实际光斑是散斑—— 这种情况在容量不足的代理上很常见。验收标准永远是实场，不是代理输出。

06

写差异表，然后才写结论

把每一处替换、每一处省略、每一处精度损失列成表，标出它对结论的影响方向与量级。 结论只能写在差异表允许的范围内——这一步决定了这份复现能支撑多强的话。

站点是纯静态的，没有构建步骤：样式、脚本、数据各一份，所有页面共用。

03Add

新增一篇：三个动作

整套结构就是为这件事准备的。做完这三步，门户首页与页间导航会自动接上。

01

在 projects.js 里加一条记录

放在数组最前面，新的排在上面。

assets/data/projects.js 
{
  slug: "your-paper",              // 同时用作文件名与图目录名
  status: "done",                  // done | wip | plan
  statusText: "已复现",
  venue: "期刊 · 年份",
  title: "论文标题的中文表述",
  sum: "两三句话说清做了什么、结果如何，不写形容词。",
  cover: "assets/img/your-paper/cover.jpg",
  kpis: [
    { v: "0.0082", k: "指标名" },
    { v: "10 类", k: "覆盖范围" }
  ],
  tags: ["框架", "方法", "器件"],
  href: "reproductions/your-paper.html"
}
02

把 _template.html 复制成项目页

改成 reproductions/<slug>.html，然后只填正文。 页头、面包屑、章节条、页脚、灯箱都不动——它们已经写好了。

03

放图、接导航

图片放 assets/img/<slug>/，尺寸压到宽 ≤ 1300 px。 最后把相邻两页的「上一篇 / 下一篇」互指一下。

04Rules

写作与制图规范

这些规则不是审美偏好，是为了让读者能比较不同项目、能判断结论强度。

项规则理由
章节基础 / 论文 / 结果 / 方法 / 上手 / 下载 / 引用，有界面的插「GUI」换一篇论文时阅读路径不变
差异表每篇必须有「论文做法 / 本复现做法 / 影响」三列结论的适用范围由它界定
结果图必须注明来源与口径：谁的图、什么条件、单位与比例尺避免把论文原图当成自己的结果
数字只写自己跑出来的数，并给出对应命令读者要能复算
图片宽 ≤ 1300 px；照片类用 JPEG q86，线稿用 PNG首屏加载时间
文案只讲方法与结果的差异，不把硬件条件、运行速度当作成果这些不是方法贡献，写进去会稀释结论
术语首次出现给全称与一句话解释，之后用缩写跨领域读者能跟上
未完成用 warn 标记，不要隐去省略会被误读为已完成

关于最后一条：复现的价值不在「全部做出来了」，而在「说清了做到哪、没做到哪、为什么」。 一份诚实的差异表比一张漂亮的对比图更能支撑后续工作。
